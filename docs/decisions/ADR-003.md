# ADR-003: Document payloads on localhost (DB bytea) with an S3-compatible swap seam

## Status

Accepted

## Context

ADR-001 mandates private object storage with metadata-only rows. On a
localhost academy deployment there is no bucket, no MinIO, and no cloud
account — standing one up would trade demo reliability for ceremony.
The product contract that matters (spec §6/§7, acceptance 7/8/9/11) is
behavioral: authorized-only upload/delete, API-brokered downloads, strict
file validation, no public URLs, 30-day purge.

## Decision

1. Payloads live in the `data` bytea column (5MB cap enforced before write).
   Rows carry the full ADR-001 metadata shape: storage key, filename, MIME,
   size, SHA-256 checksum, uploader, purge date, soft-delete timestamp.
2. The swap seam is three private methods on `DocumentsService`
   (persist/read/drop by storage key). A production host implements an
   S3-compatible backend behind the same three methods, gated by `MINIO_*`
   env vars, plus the existing backfill-on-boot pattern. No controller,
   route, validation, audit, or UI code changes when swapping.
3. If `MINIO_*` is ever set without an S3 backend present, the service logs
   a warning and stays on the database backend — a missing bucket must
   degrade to working storage, never to failed uploads.
4. Retention purge runs daily in-process and is unit-tested directly
   (deterministic, no clock mocking in e2e).

## Consequences

- All acceptance criteria hold on localhost: type rejection, delete
  semantics, 404 on missing/purged payloads, automated purge.
- Production still follows ADR-001 literally; this ADR only selects the
  localhost backend behind the documented seam.
